# 当前实现流程

## 输入、第一轮与候选

输入是 N×M 整数表、公开属性值域、客户端属性划分和配置。
默认按列序均匀划分 K=4 方。Item 使用 `(attribute_id, value)`，itemset 是排序后的 item 元组。

总预算 ε 中第一轮占 rε、第二轮占 (1−r)ε。noisy N 消耗第一轮的 10%，
因此默认 r=0.5 时三个分量为 0.05ε、0.45ε、0.5ε。
各客户端按其预算独立发布 noisy N，服务器取均值并截断到至少 1。

第一轮对每方完整公开值域的单项直方图加 Laplace 噪声，然后每方按 noisy count 保留至多 k 项。
服务端聚合，再保留全局 top-k 单项。合法候选的猜测支持数为

`noisy_N × product(clip(noisy_item_count / noisy_N, 0, 1))`。

所有长度 1–4 的合法候选在同一支持数尺度上排序，广播至多 2k 个候选 S。
候选数不足时保留实际可构造数，不伪造候选。

## 第二轮 MAP-M

客户端将 S 投影到本地属性。把相关单项键和实际出现的非空本地联合投影去重，
利用第一轮已发布计数构造单项/联合键的猜测支持数，混合排序后每方至多上传 k 个键。
键选择依赖第一轮发布内容，不读取本地原始支持数来重新决定排名。

同一属性投影的互斥取值键可复用测量组预算。`mixed_joint_budget_weight>0` 启用这套逻辑，
不同正值在当前代码中不代表不同的倍数权重。设为 0 才是完全逐键均分。
不同投影可能被同一记录同时命中，隐私会计使用公开重叠上界和坐标 ε 计算联合 RDP 界。

每个键定义一个本地支持用户 ID 集合。相同用户、相同 sketch 坐标的共享秩一致，
客户端计算集合 Alpha，并由 DP-FM 机制加入保护所需的虚拟元素/截断，而非简单对 Alpha 加 Laplace 噪声。
服务器仅以报告的 Alpha 和参数构建 MAP 估计。

单一支持集合使用边缘 MAP。跨多个集合时，先获得边缘基数估计，构造集合论可行支持数区间，
在离散搜索点上使用均匀先验和 Alpha 联合似然，取后验最大点。
本地联合 Alpha 优先减少需要跨集合估计的部分，嵌套单项/联合报告由现有联合似然处理。
min Alpha 本身不是交集支持数的最终估计。完整数值公式与具体近似分支以 `privfim/dpfm.py`
和 `privfim/server.py` 为准，原理论笔记保留于 `map_theory.md`。

MAP-S 只上传目标单项。MAP-L 上传候选的全部实际唯一非空本地投影，不设 k 上限。
MAP-M 缺少估计候选所需键时，候选可能不可估计，其遗漏计入外层全局评价。

## 并补与 FO

IE-Full 对相关属性完整值域分桶报告。IE-Other 将未点名值归为每属性一个 OTHER 桶。
服务器估计目标属性值之外的并集，然后返回 noisy N 减该并集。预算由实际桶数决定。

FO 使用 OUE 处理第一轮单项报告及第二轮对齐用户的目标键成员报告，通过去偏乘积估计交集。
它的本地报告预算模型与机构端统计加噪不同，结果保留模型名称，不把 FO 与 DP-FM 的噪声机制混为一谈。

## 单轮消融与评价

First-round 将总预算的 10% 用于 noisy N、90% 用于计数，不收集 Alpha。
Second-round 预先报告本地公开值域中所有单项、二项、三项 Alpha，5% 总预算用于 noisy N，
95% 用于 Alpha，不接收 S 后再选择报告。Items-only 是只报告单项的额外消融。

所有发布方案分别评估，多个方案的联合发布预算没有自动组合。
协议之后才计算独立完整真值，并核对同一数据变换下全局 top-k。
离线真值、错误分析和原始支持数文件是实验评价材料，不是应发送给服务器的协议消息。

## 隐私与系统边界

实现用公开可复现 seed 和 SplitMix64 生成共享秩，属于实验仿真。
条件 RDP 核算依赖服务器未知的共享随机性/秘密 PRF 等前提，仓库没有完成秘密 K 的分发与生产 PRF 接入。
因此保留 `formal_end_to_end_dp=false`，不把会计数值通过当作当前可复现实验种子已提供生产隐私保证。
客户端与服务器角色在一个进程中运行，不计网络延迟和私有实体对齐开销。
